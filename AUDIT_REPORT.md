# VisaPro Website Audit — Executive Summary

## 1. Overall Health

The audited surface of VisaPro is in **poor functional health**, dominated by a systemic problem: **multiple user-facing and admin-facing pages display fabricated mock data while presenting it as real**, and several primary actions are wired to dead or stubbed handlers that silently fail. The entire **fonts feature** (`frontend/src/app/fonts/`) is non-functional end-to-end — its data layer in `frontend/src/services/api.js` consists of "LEGACY STUBS" that never call any backend (no fonts module exists server-side), so every font, price, rating, and stat a visitor sees is hardcoded demo content. Two **admin consoles** are worse than broken: the messages inbox (`admin/messages/page.jsx`) shows four fake contacts and lets admins "reply" via a button that fires a misleading "Reply sent!" toast without transmitting anything, while the visa-applications console (`admin/visa-applications/page.jsx`) silently falls back to 8 fabricated applications (with `XXXXXXX` placeholder phone numbers) on any API failure, exposing View/Update/Delete actions against records that do not exist. Beyond data integrity, there is a recurring pattern of **dead buttons** (Refresh, Load More, Share, preview, wishlist) that render but do nothing. The most acute risk is **admin trust and correctness**: staff cannot distinguish real records from fakes, and confirmations lie about actions that never happened. None of these issues are cosmetic — they go to the core reliability of the product.

## 3. Cross-Cutting Patterns

- **Mock data masquerading as real, used as a *silent runtime fallback* — not just dev scaffolding.** This is the dominant theme across all four files (`admin/messages`, `admin/visa-applications`, `fonts/page.jsx`, `fonts/[slug]/page.jsx`). In every case a hardcoded array is wired into the render path so that API failure (or a guaranteed-failing stub) results in fabricated content shown as legitimate. **Recommendation:** replace silent fallbacks with explicit empty/error states; never substitute fake records for failed fetches, especially in admin tools that expose mutating actions.

- **A broken/stubbed service layer with missing methods (`frontend/src/services/api.js`).** The "LEGACY STUBS (fonts pages)" block (lines 235-246) is the single root cause behind findings #4, #5, #7, #10 and the related-fonts bug. The stubs both (a) always return `success:false` and (b) omit methods the pages actually call (`getById`, `toggleLike`, `checkAccess`), so call sites throw `TypeError`. There is **no corresponding backend fonts/cart/download module** at all. **Recommendation:** either fully remove the fonts/cart feature from the UI or implement the backend + complete the service; do not ship pages that call non-existent methods.

- **Fake success confirmations on no-op actions (user-trust hazard).** "Reply sent!" (`admin/messages/page.jsx:35`) is the worst offender — it actively lies. The Add-to-Cart spinner-without-result is a milder variant. **Recommendation:** gate all success UI strictly on a real successful response, and surface failures.

- **Dead buttons that render full affordances but have no `onClick`.** A consistent omission across the fonts feature and admin messages: Refresh, Load More, Share, Eye/preview, Heart/wishlist. Sibling buttons in the same containers *do* wire handlers, confirming these are unintentional gaps rather than intentional placeholders. **Recommendation:** audit interactive elements for missing handlers (and remove buttons for features that don't exist yet).

- **Note on intent:** the `api.js:235` header "LEGACY STUBS (fonts pages)" suggests the fonts feature may be deliberately abandoned scaffolding in this VisaPro app. If so, the cleanest fix is to **delete the entire `frontend/src/app/fonts/` tree and its stub services** rather than repair them — but as long as the pages are reachable, the fabricated-data and dead-button findings stand.

**generateSlug() .trim() is ineffective — runs after spaces are converted to hyphens, so leading/trailing whitespace yields leading/trailing hyphens in slug**
